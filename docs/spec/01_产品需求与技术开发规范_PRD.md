# CET-4 Study OS V1.0｜产品需求与技术开发规范（PRD）

> 状态：50/50需求调研完成；正式的“需求确认/开发依据”版本，尚非已交付软件。  
> 需求冻结日期：2026-10-23；适配：Windows 11 + Microsoft Edge；使用者：单人。  
> 核心验收原则：稳定、少Bug、数据不丢失、真题可信、训练/模考可用。  
> 用户第50题最终选项：**D，完整工程化交付**。

## 0. 项目一句话定义

面向个人的**Windows本地Web英语四级训练工具**。用户双击桌面快捷方式，在Edge浏览器中使用本机学习平台，自主选择真题及题型，日常训练不计分、可以随时查看答案；正式模考遵守四级流程并仅统计客观题；系统提供真题导入校验、听力分题播放、三类阅读交互、错题闯关、成绩趋势、自动保存和备份恢复。**平时使用不能依赖ChatGPT对话，不需要登录账号、在线服务器或每日固定学习计划。**

这份规范以本轮50道题的回答为最高优先级，替代前期原型及早期云端方案中发生冲突的设计。不得将曾经提出、后来明确否决的功能重新写入默认开发范围。

## 1. 目标、边界与核心事实

**目标考试**：2026年12月12日9:00—11:20英语四级笔试，备考目标为425分。该考试日期以中国教育考试网2026年下半年公告为准。  
**考试题型**：作文1题/30分钟；听力短篇新闻7题、长对话8题、篇章10题/25分钟；阅读选词填空10题、长篇阅读段落匹配10题、仔细阅读10题/40分钟；翻译1题/30分钟。题目总数57（含作文和翻译）。  
**官方成绩**：四、六级报道分为常模参照，并非单纯由“客观题正确率×710”得出。本系统不计算官方总分，不标注“已经达到425”。

**不做（本期明确排除）**：
- 用户账户、注册、多人使用、联网云同步、网页公开部署；
- 每日51天自动排课、自动指定练习题目、每日任务打卡；
- 日常练习分数及日常答案是否提前查看的追踪；
- AI自动批改写作翻译、在线写作输入框、作文照片上传；
- 在线自动更新、Windows以外操作系统的适配；
- 依赖每天向ChatGPT发送“开始第X天”或提交成绩的工作流。

**保留的自动化**：自动保存学习历史、数据备份、导入后校验、错题闯关抽题、模考计时/收卷/客观题判分及趋势统计。取消自动排课≠取消这些自动化工具。

## 3. 主要用户流程与页面

### 3.1 导航（PC优先）

左侧固定导航：`首页`、`真题库`、`听力训练`、`阅读训练`、`写作/翻译资料`、`模考中心`、`错题闯关`、`成绩趋势`、`导入中心`、`设置与备份`、`故障诊断`。根据开发阶段逐步开放；未开发页面应清晰显示“此功能在下一阶段”，不可放置无响应按钮。

首页仅展示“今日使用历史 / 最近使用真题 / 开始自由练习 / 今日错题闯关 / 最近一次模考结果 / 数据状态”。**不显示强制的51天每日课程，也不要求点击‘今日任务完成’。**

### 3.2 真题导入流程

1. 用户先手动指定 `年份`、`6月/12月`、`第几套`，创建或选择一个试卷容器；唯一键`(year, session, set_number)`。
2. 分别在3个入口上传`试卷`、`听力音频`、`答案解析`。允许一次上传若干文件但每个文件必须归类。
3. 保存原始文件及SHA-256校验和；阻止危险路径、超大文件与损坏文件；显示解析进度及文件状态。
4. 先进行确定性的文本抽取（电子PDF、DOCX）；扫描PDF及图片走离线OCR；音频读取格式、时长并检查解码；OCR及复杂排版结果一律视为**待验证**。
5. 解析为结构化试题：题号、题型、文章/段落、选项、标准答案、解析、试卷来源。应用校验规则：题型数量、题号范围、唯一性、缺失、答案合法值、解析映射、重复文件、音频可播放性等。
6. 通过者启用普通训练；未通过者在检查报告中显示原因并禁用。校验**只能判断结构可靠，不代表已自动证明正确答案一定可信**，重要资料应人工核对原件。
7. 原始文件修复方式是**重新上传**（第10题B），而不是在网页中手动重写题目；系统尝试仅更新确定匹配的题目，保留历史记录；无法匹配必须展示新旧对照、用户确认映射后才提交。
8. 为完整模考设置“可用条件”：作文题/听力完整MP3/25道听力客观题/30道阅读客观题/翻译题/答案/合法题序和时长全部具备并通过校验，音频分段（供日常用）如果质量不合格不阻断已有完整MP3用于模考，但具体标识需准确。

**重要可行性边界**：不同出版社的扫描版真题和图片不可能保证100%自动识别；仅重新上传**完全相同且同等清晰度**的损坏原件，不会自动消除OCR错误；此类情况必须提示用户重新提供质量更好的源文件，或在本地外部工具中修正后重传。禁止猜测缺失答案，禁止无提示开启有疑问的试卷。

### 3.3 音频切分（第15、16、17题）

- 原始完整音频必须保留且永不在导入中覆盖，日常和模考通过文件引用使用；
- 使用音频静音区间/停顿检测等算法**建议**片段起止点，再依据题组划分（1段新闻/长对话/篇章可对应多题）；不承诺算法能自动理解题号关系；
- 预览界面显示题组范围、开始/结束时间和播放按钮，用户必须确认；
- 被拒绝的切分不能用于日常分题播放；系统显示缺失提示，允许用户重传来源资料后再次识别；
- 日常：点击题目播放其所属**题组音频**，可暂停、倍速、拖动、重复播放，可看原文答案；
- 模考：仅调用完整MP3，从规定阶段开始连续播放，禁用应用级暂停/seek/重复/倍速；不使用题组音频来冒充完整模拟。

**产品风险提示**：若自动定位长期无法可靠完成，既定“分题播放”功能会受影响，此项是P0重点验收门槛。开发前应先用用户实际音频验证切分策略；不能仅用自制标准样例判定通过。

### 3.4 日常自由训练

- 自由选择年份、月份、套数、题型和具体题组；系统不代替用户安排训练日程。
- 听力日常可以随时查看原文/正确答案/解析。
- 阅读左右分栏，独立滚动；文章和题目始终可以同时查看。仔细阅读点选单选项；段落匹配可把相同字母用于不同题；选词填空每词一次，撤销、重选和释放占用一致。
- 每次切题、选答案、收藏错题、播放定位等有意义的操作记录历史；后台持久化写入并在UI显示成功/待写入/失败状态。重开后继续最近的日常训练。
- **日常不显示统计分数、不排名、不检测答案查看行为；可以做题，但不因对错改变模考成绩。**
- 写作翻译：只显示题目、范文/参考译文、解析；用户线下书写，不采集答案。

### 3.5 正式模考

必须遵守2026年公开的四级笔试总体考试时段9:00—11:20以及典型考务顺序：

| 相对开始时间 | 对应实考时钟 | 模拟内容与界面规则 |
|---|---|---|
| 00:00—10:00 | 9:00—9:10 | 发卷/须知模拟，显示注意事项，禁止提前答题 |
| 10:00—40:00 | 9:10—9:40 | 写作30分钟；网站展示题目，纸笔作答；无AI批改 |
| 40:00—65:00 | 9:40—10:05 | 完整听力音频连续播放，听力单选题作答 |
| 65:00—70:00 | 10:05—10:10 | 模拟收答题卡1，锁定听力；中断答题 |
| 70:00—140:00 | 10:10—11:20 | 阅读和翻译共70分钟，题目遵循真实要求；翻译线下完成 |
| 140:00 | 11:20 | 自动交卷、锁定全部答题区，客观题判分 |

上表为公开考务安排的模拟化描述。正式实现需确保与最终获取的最新考务说明一致；若考试要求调整，应更新配置并纳入测试，不硬编码不可修改的魔法时间。

- 模考开始前运行**整卷完整性、音频时长与解码、系统时间、数据库、磁盘空间及备份可用性**的前置检查。缺少标准答案或MP3不可开启正式计分模考。
- 模考中严格隐藏所有正确答案、解析和原文；结束后开放。
- 浏览器刷新、崩溃、关闭、操作系统掉电、应用进程中断：保留已答内容，标记`interrupted`，不计入正式成绩；可以重新开始一次新的attempt。刷新也可能触发中断，这是用户选定的严格模式，应在开始前醒目告知。
- 到点且服务正常运行时自动交卷；必须用持久化时间戳与服务器状态机校验，不能只靠浏览器倒计时。禁止重复提交和跨阶段篡改旧答题卡。
- 技术边界：本地网页无法绝对控制操作系统静音、耳机断连或用户运行浏览器开发工具，所谓“严格”是**应用行为约束**而非监考级防作弊承诺。

### 3.6 成绩与趋势

客观题按：新闻7、长对话8、篇章10、选词填空10、匹配10、仔细阅读10，合计55道。展示各题型：`答对数/总数`、正确率、历次正式**完成**模考折线图、日期与来源。作文与翻译标记`未评分`。中断模考不进入趋势。

**不得显示“总分425 / 710预估”**；也不应把55道原始正确数当作官方等值分。遇到历史试卷题数异常、答案有争议或变更后重新校验的情形，显示`成绩待复核`并从趋势中暂时剔除，保留历史原始成绩快照与变更原因。

### 3.7 错题库与每日闯关

- 来源1：完整且有效的正式模考，自动把客观错题入库；来源2：日常训练手动点击“加入错题本”。同一真实题目标识去重，但可以合并多次来源记录。
- 题目若因重上传被禁用，关联错题不能丢失；暂停参与闯关直到确认题目/答案恢复有效。
- 每天生成一次5—10道的复习集合（如果不足则按现有数量生成，不凑数；没有错题显示空态）。
- 混合排序权重兼顾近期新增、长时间未复习、频繁错题；减少相邻日期重复。算法固定、可单元测试、可解释。注意不能为了避免重复而永远遗漏错误多的题。
- 一题一次提交后立即显示正确答案和解析；**首次提交决定该日结果**，不允许反复点同题刷次数。跨不同日闯关连续3次答对后标记掌握，不再参加日常抽取，历史保留；任一次答错连续次数归零。
- 日常闯关结果只用于错题复习状态，**不进入正式模考成绩**。闯关不是取消51天课程后新增的强制每日任务，用户可不参加。

## 4. 数据与可靠性要求

### 4.1 推荐数据布局

- 程序及静态网页：`C:\Program Files\CET4 Study OS\`（用户可修改安装位置）。
- 用户数据（SQLite、导入原件、解析产物和备份）：`%LOCALAPPDATA%\CET4StudyOS\`。
- 安装卸载默认保留用户数据，清除数据需要单独明确确认。
- 禁止把用户导入的教材、真题、音频和数据库提交到公开GitHub仓库。
- 数据库存储采用SQLite WAL + `foreign_keys=ON` + 事务；写入成功才报告“已保存”；定期运行`PRAGMA integrity_check`。

### 4.2 实时自动保存

- 读题位置、题目选择、收藏、答题进度变化后持久化；写入冲突需要事务和重试（有限次数），失败不得假装成功。
- UI应区分：`已保存`/`正在保存`/`保存失败—可重试`。重启能恢复最后成功落盘的操作，不承诺物理断电时零丢失。
- 模考每步作答也落盘，但异常中断按已确认规则只保留内容、不计正式成绩。

### 4.3 备份与恢复

- 每天首次打开（或本地服务运行到设定时间）执行一次自动备份；断电离线导致错过备份时，下次启动补做。用户不需要保持电脑24小时开机。
- 提供“立即备份”“恢复备份”“导出数据”；备份范围**包含数据库、上传原始文件和关联配置**，不得只拷贝空数据库而遗漏音频。
- SQLite必须使用在线备份API或经过正确事务协调的快照手段，不能在数据库打开时随意复制WAL文件。
- 备份生成临时文件→校验文件清单/哈希与数据库一致性→原子更名→登记；磁盘空间不足时明确提示。
- 恢复先备份当前状态；校验备份内容、版本、路径安全性；二次确认后在本地服务安全停止写入的状态恢复；恢复失败可回到原状态。
- 默认保留至少7个最近每日备份（建议值，允许配置）；同一硬盘备份无法抵御硬盘整体损坏，所以手动“导出数据”应能另存外置盘。

### 4.4 历史题目修订

- 题目具有稳定主键+内容版本号+所属试卷；更新保留旧版本快照，不用覆盖删除。
- 自动匹配只能在明确确认时完成；模糊匹配走新旧对照确认。
- 旧模考结果按当时版本保留原始答题快照；若标准答案变更，建立`score_revision`标记与重新判题记录，绝不悄悄改旧报告。

## 5. 技术建议（非用户直接指定，由需求约束推导）

**推荐技术栈（开发前固定依赖版本并实际验证）**：
- 前端：React + TypeScript + Vite，构建为静态网页资源，在本地Web服务中托管；
- 后端：Python + FastAPI；本地独立进程仅监听 `127.0.0.1`；
- 数据：SQLite + SQLAlchemy + Alembic迁移；
- 导入：PyMuPDF（需核查许可证及分发条件）或其他许可兼容的PDF文本提取器、python-docx、离线OCR引擎（安装包一起分发）；
- 音频：服务端FFmpeg/ffprobe（需确认分发许可证）或可替代许可合规音频库验证时长、声道、切分建议；Edge原生HTML5音频播放；
- Windows打包：PyInstaller等打包器 + Inno Setup等安装工具，最终输出一键安装`.exe`；
- 测试：Pytest + 前端单测（Vitest）+ Playwright（Edge/Chromium）+ Windows安装/卸载/升级脚本。

这些是**建议的实现方案**，不是宣称已经安装验证。正式开发前须完成第三方依赖许可检查、Windows 11真实机器验证、构建复现。**前期提出的Vercel/Supabase云端方案已被第1、2、43题否决，不应继续沿用。**

**本地服务安全**：只监听回环地址；启动器使用进程互斥避免重复启动；随机空闲端口或可控固定端口；启动后通过`/healthz`验证再打开Edge；HTTP API校验`Origin`/CSRF、上传格式/大小和本地文件路径，防止恶意网页跨站请求访问本机应用。免登录不等于免安全设计。

**旧版Word `.doc`**：如果需直接支持，只能在有合规转换组件/已安装Word时执行受控转换；否则明确提示“请转成DOCX重传”。这是技术兼容边界，不可假装所有DOC都能被直接解析。

## 7. 关键非功能指标及验收门槛（工程建议值）

- **数据丢失0容忍**：常规刷新/重启后不丢已确认写入的数据；备份恢复演练应恢复所有题目、媒体与记录；单项失败明确报错。
- **准确优先**：每次正式模考开始前检查55道客观题、标准答案、完整音频；**不得用不完整或校验失败的试卷启动有效模考**。
- **稳定优先**：测试中出现导致无法启动、丢数据、错判、错收卷、错题对应错误的P0缺陷，阻止发布。
- **桌面体验**：在Windows11/Edge标准桌面分辨率（建议1366×768及1920×1080）核心操作无横向溢出/遮挡；导入大文件提供进度与错误提示。
- **性能建议值**：热启动本地服务后Edge首页通常应在5秒内可交互（测试基准需标注电脑配置）；普通题目切换尽量<300ms；文件导入耗时随OCR和文件大小变化，不承诺固定秒数。
- **安全**：服务仅回环监听，接口不能任意读取本地路径；外部字体/CDN断网时不影响训练；第三方资源许可证已审核。
- **可交付性**：在干净Windows11测试机上运行exe，无需手动安装Python/Node；卸载重装后已有数据仍可恢复；干净GitHub检出可按README构建。

详细测试样例见 `04_验收测试与故障注入.md`。

## 8. 当前已知难点与尚待实际验证项

1. **OCR与混合文件结构提取**：人工上传≠自动解析一定准确。尤其图片扫描、复杂排版、答案与题目跨文件匹配，需要真实样本测试；不清楚的数据不得被当作已验证题。
2. **自动推荐音频切分**：分题播放要求高，候选片段可能错误，必须人工试听确认；需要真实音频素材验证边界识别效果。
3. **免在线评分但严格作文/翻译模考**：用户线下书写，系统只能控制该阶段的时序，无法自动判断作文是否实际完成，不应当写入“已阅卷”。
4. **文档中的旧计划冲突**：第23/24题明确取消每日训练排课，因此早期51天逐日计划仅作为备考背景，不是程序默认功能。
5. **原型并非正式系统**：此前单文件HTML原型、在线Supabase/Vercel架构不能证明Windows本地程序可用，需重新按本规范工程化实现与验收。
6. **恢复能力边界**：备份保存在同盘无法防止盘损坏；需引导用户偶尔导出到外置存储。
7. **真题版权**：用户提供的试卷与音频仅用于本地个人学习，开发仓库不应默认公开上传这些内容，真题格式样例应使用自编测试数据或获得授权的素材。
