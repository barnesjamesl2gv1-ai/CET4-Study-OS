# GitHub-first reuse（先搜索，后开发）

目标：尽量复用可靠的开源代码/依赖，**不是不经审核地复制仓库**。本 Skill 是研究、决策和集成流程；它本身不授予安装第三方代码、执行远程脚本、联网传输用户文件或更改既定需求的权限。

## 何时使用

- 开发非平凡能力、解决不熟悉的技术问题、选择依赖、涉及 OCR/PDF/音频切分/Windows 打包/数据库恢复等难题时，主动运行。
- 当前库已有成熟实现时也应检查版本、文档和维护情况；小型明显的本地修复不必为形式而另找库。
- 严格遵守仓库 `AGENTS.md` 与 `docs/spec/` 的已确认 50 项需求。技能不能覆盖产品要求或质量门禁。

## 操作流程（不可跳过结论与验证）

1. **定义问题与边界**：明确输入输出、运行环境（单人 Windows 11 + Edge，本地 FastAPI/React/SQLite，重要功能离线）、验收用例及是否有现有依赖可复用。
2. **实时检索 GitHub**：优先使用可用的 GitHub 搜索工具、`gh search repos`、或本目录脚本 `python .agents/skills/github-first-reuse/scripts/github_candidates.py '关键词' --language Python --limit 8`。按功能名、同义词、技术栈至少尝试两组精准检索词；查 README、源码、release、测试和 LICENSE。检索不可用时如实记录，不可捏造候选、星标、最近更新或搜索结果。
3. **比较候选**：通常筛出 2–3 个（数量不足说明原因）；比较任务匹配度、离线适配、Windows兼容、Python/TS接口、维护活跃度、Issue/测试状况、安全风险、集成复杂度和依赖规模。星标不能替代质量评估。
4. **先过许可证关**：核对源仓库明确的 `LICENSE`、版权声明及所需第三方依赖许可证；**没有明确许可不复制源码**。MIT/BSD/Apache-2.0 等也必须满足版权/NOTICE等义务。GPL/AGPL/LGPL、非商业、自定义、许可不明等情形先报告风险并取得明确许可或改选；未经审核不得复制、vendoring 或合并代码。许可证验证是人工/工具辅助工作，不能仅相信搜索结果里的字段。
5. **做最小集成决策**：优先现有依赖或稳定发行包及其官方 API，其次受控的最小子模块；不整仓复制，不盲目复制网络代码，不执行来路不明的 `curl | sh` / 安装脚本。锁定版本/提交 SHA、明确使用边界；保护用户真题、音频、数据库和密钥，不上传给外部服务。引入新依赖时检查漏洞公告、传递依赖与更新策略。
6. **先做小型可复现实验**：为实际需求写最小适配器、合法样例、失败/异常测试；对于扫描 OCR 和音频识别等不确定性，必须用用户授权的本地真实资料确认边界，不得把模拟测试称为真实验收。不可复用或风险大时说明为什么选择有限自研。
7. **完成集成与记账**：遵照 `AGENTS.md` 更新相关测试、运行全部应跑验证、创建 Git commit。涉及实质引入时，在 `docs/oss-reuse/<topic>.md` 记录来源仓库链接、具体版本/commit、许可证/NOTICE、候选比较、使用文件/API、集成差异、测试证据、回退方式和已知局限。公开仓库禁止提交第三方受限资料和用户原始真题。

## 失败与权限边界

- 搜索 API 限流/无法联网：换可信可用搜索入口；仍不可用则报告阻断与可验证的替代方案，**不能声称已完成 GitHub 搜索**。
- 无合格候选：允许最小范围自研，但必须列出不复用原因和测试证据。
- 不能为了“复用”突破验收门禁、删除既有功能或修改 50 题需求；复杂的架构替换先提出方案。
- 用户仅要求调研时，不自动安装依赖、复制仓库、运行第三方代码或推送变更；获得明确实施授权后才集成。

## 每次输出

简明报告：**问题 → 检索关键词与时间 → 候选对比（附 GitHub 链接）→ 许可证判断 → 复用/不复用决策 → 具体集成与测试结果 → 提交哈希或阻断原因**。使用 `references/reuse-decision-template.md` 记录重大复用决策。
